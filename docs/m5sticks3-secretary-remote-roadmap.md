# M5StickS3 秘書リモコン → 表情・状態表示端末 ロードマップ

最終更新: 2026-07-01 01:18:36 JST

> For Hermes: この文書は、余った M5StickS3 をまず「秘書リモコン」として実用投入し、その運用知見を使って最終的に「くろー/Hermes の表情・状態表示端末」へ進化させるための段階計画である。

## Goal

余った M5StickS3 を、
1. まずは日常で実際に役立つ「秘書リモコン」として作り、
2. 使って得た操作データと利用文脈を観察し、
3. その知見をもとに「相棒感」のある表情・状態表示端末へ育てる。

## Architecture

初期段階では、M5StickS3 は「入力デバイス」として振る舞い、Hermes 側へ HTTP / webhook ベースで短い指示を送る。第2フェーズでは送信イベント・利用頻度・不足機能を記録する。第3フェーズで、入力端末から状態表示と感情表現を持つ常設 companion 端末へ役割を拡張する。

## Tech Stack

- Device: M5StickS3
- Firmware候補: ESP-IDF + M5Unified
- 通信: Wi-Fi + HTTP / webhook（必要に応じて後で WebSocket）
- Hermes連携: webhook / API / 既存の gateway 連携
- 保存/観察: ローカルログ、簡易イベント集計、必要なら Obsidian へ要約

## フェーズ1: M5StickS3 を「秘書リモコン」として作る

### 目的
スマホを開かずに、Hermes へ用件を素早く投げる物理ショートカット端末を作る。

### この段階で狙う価値
- 思いつきの取りこぼしを減らす
- ADHD対策として「脳内一時退避」を物理ボタン化する
- 予定、メモ、出費、次タスク確認の摩擦を下げる

### Phase 1 MVP

#### MVP機能
1. メモ送信
   - 例: 「思いつきメモ」モードに入って定型イベント送信
2. リマインド起点
   - 例: 「あとでやる」イベント送信
3. 次タスク表示
   - Hermes 側へ問い合わせて、短い次タスク1件を画面表示
4. 送信結果表示
   - 成功 / 失敗 / 再試行を画面に出す

#### 後回しにするもの
- 音声入力
- 常時接続 WebSocket
- 複雑な自然言語入力
- 表情アニメーション
- 本格的な通知センター

### UI案（初版）
- 画面トップ: 3メニュー
  - Memo
  - Remind
  - Next
- 操作案
  - BtnA: 上/左へ移動
  - BtnB: 下/右へ移動
  - 長押し: 決定 / 送信
  - 電源/補助ボタンが使えるなら: 戻る
- 送信後
  - `送信中...`
  - `OK: メモ送信`
  - `NG: Wi-Fi未接続`

### Hermes 側インターフェース案

#### まずはイベント型にする
M5StickS3 側で自由文を捌こうとせず、まずは固定イベントを送る。

例:
- `secretary.memo.capture`
- `secretary.reminder.quick_add`
- `secretary.task.next`

#### 最小 payload 例
```json
{
  "device": "m5sticks3-secretary-remote",
  "action": "secretary.task.next",
  "timestamp": "2026-07-01T01:00:00+09:00"
}
```

### フェーズ1の実装順
1. M5StickS3 の画面・ボタン・Wi-Fi 接続だけ確認
2. 固定メニュー UI を作る
3. Hermes webhook へ定型 JSON を送る
4. 成功/失敗レスポンスを画面表示する
5. 「次タスク表示」だけレスポンス描画を追加する
6. 実生活で使い始める

### フェーズ1で観察したいこと
- どのメニューが一番使われるか
- 押しやすい操作体系は何か
- 送信結果の表示はどの粒度が必要か
- 「本当はこの場面で状態が見えたかった」がどこにあるか

## フェーズ2: 使ってみて本当に必要な状態を洗い出す

### 目的
リモコンとして運用しながら、「入力」だけでは足りない場面を発見し、状態表示端末へ進化させるための材料を集める。

### この段階で集める情報
1. よく使う入力
   - メモ
   - リマインド
   - 次タスク
   - 出費起点
2. 欲しくなる状態表示
   - 未処理タスク件数
   - 次の予定
   - リマインド待ち件数
   - StackChan 接続状態
   - Hermes 応答中かどうか
3. UX上の不満
   - 押し間違い
   - 1画面の情報量不足
   - Wi-Fi待ちのストレス
   - 成功したのか不安になる

### 観察方法
- 送信イベントを action 単位で集計
- 使った時間帯をざっくり記録
- 1日1回、「欲しかった表示」を短くメモ
- 週次で振り返り

### 観察ログ項目
- 日付
- 使った回数
- 使った action
- 失敗回数
- 欲しかった状態表示
- いらなかった機能

### フェーズ2の出口
以下が決まれば次へ進む。
- 常設表示するべき上位3状態
- ボタンに残すべき入力操作
- 画面の主役を「入力」から「状態表示」に変えるべきかどうか

## フェーズ3: 「表情・状態表示端末」に進化させる

### 目的
秘書リモコンの実用性を残しつつ、くろー/Hermes の存在感を見える形にする。

### 目指す体験
- 机の上に置くと、今の Hermes/StackChan の状態が一目でわかる
- 押せば用件を送れる
- 見るだけでも「相棒がいる感じ」がある

### 表示したい状態の候補
- 待機中
- 聞いてる / 受付中
- 処理中 / 考え中
- 通知あり
- エラー
- 次の予定あり
- タスク詰まり気味

### 表情の対応案
- 待機中: 眠そう / ふつう顔
- 受付中: 目が開く / 聞いてる顔
- 処理中: くるくる / 考え中
- 通知あり: ぴこん顔
- エラー: しょんぼり顔
- 完了: どや顔 / にっこり

### 端末の役割再設計
- 主役: 状態表示
- 副役: 入力ショートカット

### フェーズ3で増やす機能候補
- 顔アニメーション
- 状態ポーリングまたは push 更新
- 小さな予定表示
- 未処理件数表示
- StackChan 本体との連携状態表示
- 押下時だけショートカットメニュー表示
